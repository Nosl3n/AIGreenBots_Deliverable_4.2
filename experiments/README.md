# Experiments (E1–E5)

Experiment campaign for the Husky A300 stack in the simulated apple orchard (`husky_apple.wbt`). Everything in this
folder is **additional**: with every switch at its default, the stack behaves exactly as with `./apple.bash`.

| Id | What it measures | Stack · driver | Variants |
|---|---|---|---|
| E1 | Localization with degraded GNSS: p50/p95 error, heading, NEES (≈ 3 if consistent) | localization · `gt_driver` | `degraded` (10 seeds), `clean` |
| E2 | People tracking: MOTA, MOTP, identity switches, longest occlusion with the identity kept, false births | full · route (world `exp_people`) | `fusion` (ZED + LiDAR), `zed_only` |
| E3 | Trunk map against the world's ground truth: precision, recall, F1 (< 0.25 m), error, false trunks and wrong removals per hour | full · route | `base` (= E4), `no_lidar_confirm`, `no_pvis` |
| E4 | Integrated navigation: success, mission time, minimum clearance to trunks and people, collisions | full · route (9 waypoints) | `base` |
| E5 | Performance: rates, latencies, CPU/GPU per agent; trunk map with the semantic model slowed down | full · route | `base` (= E4), `slow_semantic` |

Results: [`results/SUMMARY.md`](results/SUMMARY.md) (machine, models, conclusions and the five reports) and
`results/report_E*.md`. Figures and screenshots in [`images/`](images/).

```
experiments/
├── configs/experiments.toml   each experiment and its variants (what is switched on/off)
├── configs/campaign.txt       the runs behind results/
├── scripts/                   orchestrator, recorder, driver and analyses
├── worlds/exp_people.wbt      E2 world (generated by scripts/gen_worlds.py)
├── images/                    screenshots and report figures
└── results/                   reports (.md) + one folder per run (not versioned, see .gitignore)
```

## Usage

```bash
cd ~/robocomp/AiGB_UEx_Navigation/experiments/scripts
python3 run_experiment.py --list                              # experiments and variants
python3 run_experiment.py E3 --variant no_pvis --seed 1        # one run (starts and stops the stack itself)
python3 run_experiment.py E4 --variant base --screenshots      # ... taking window screenshots
./batch.sh ../configs/campaign.txt > ../results/campaign.log 2>&1 &   # the whole campaign (~2.5 h), one run after another

python3 summary.py      # rebuilds every report and results/SUMMARY.md from the stored runs
```

`run_experiment.py` needs no other stack running (if there is one, it stops it first in the same order as
`./apple.bash --stop`: cognitive layer, sensorimotor layer and Webots, always with SIGINT). A run takes from 4 min
(E1) to ~6 min (full missions), start-up included.

## Switching each case on and off

Every degradation, ablation or configuration case is **one key in its component's config**, and its default value
is the normal behaviour. There are two ways to use them:

1. **With the orchestrator** (recommended): a variant in `configs/experiments.toml` is just a list of keys:

   ```toml
   [E3.variants.no_lidar_confirm.trunk_concept]
   "Ablation.LidarConfirm" = false
   ```

   The orchestrator copies the component's config into the run folder, changes those keys and starts the component
   with the copy. **The repository configs are never touched.** The modified copies are kept in `cfg/` (only for the
   components with a changed key; the rest run with the repo config).

2. **By hand, with the normal stack** (`./apple.bash`): edit the key in the component's config and restart it.

| Component · file | Key | Default | Effect when changed |
|---|---|---|---|
| bridge · `webots-bridge/etc/config_husky` | `GnssDegradation.Enabled` | `false` | `true`: the GPS fix served is the degraded one (canopies, RTK fixed/float/single, multipath, zones, outages, latency) |
| | `GnssDegradation.StatusFile` | `""` | path: writes, for every fix, what the receiver reports (σ, fix type, satellites, measurement time) |
| | `GnssDegradation.Seed`, `LatencyMs`, `OutageRatePerMin`, `DeniedZones`, `DegradedZones`, `Satellites`, `FixMinSats`, `SigmaFloatM`, … | see file | model parameters (documented in the file and in `src/gnss_degradation.h`) |
| openfield_concept · `etc/config.toml` | `Ekf.GpsSigmaSource` | `"fixed"` | `"receiver"`: R = σ² reported by the receiver |
| | `Ekf.GpsLikelihood`, `Ekf.StudentNu` | `"gauss"`, 4 | `"student"`: Student-t likelihood (down-weights multipath jumps) |
| | `Ekf.LagCompensation` | `false` | `true`: a late fix is carried forward to the current time |
| | `Gps.StatusFile` | `""` | reads the receiver report (the bridge's `StatusFile`) |
| | `Imu.UseYaw` | `true` | `false`: no absolute IMU yaw |
| | `Experiment.ShadowFilters` | `false` | `true`: also runs the E1 filters A/B/C/D on the same data (logged only) |
| | `Diag.ExperimentCsv` | `""` | path: 10 Hz CSV with every filter, its covariance, the ground truth and the receiver state |
| trunk_concept · `etc/config.toml` | `Ablation.LidarConfirm` | `true` | `false`: a trunk is born from the ZED semantic evidence alone (no LiDAR confirmation) |
| | `Ablation.VisibilityModel` | `true` | `false`: absence is charged on every look inside the field of view (no occlusion test, no range p_vis) |
| human_concept · `etc/config.toml` | `HumanLidar.Enabled` | `true` | `false`: people from the **ZED only** (no LiDAR as a second look) |
| retina · `etc/config_husky.toml` | `Semantic.decimation` | `1` | N: the ADE20K semantic model runs on one frame in N (E5) |
| robot_concept · `etc/config_husky.toml` | `Media.enable_zed`, `Media.enable_lidar` | `true` | `false` in E1: the localization stack does not relay camera or LiDAR |

## E1 details

- **Degradation layer** (bridge, `src/gnss_degradation.{h,cpp}`, plain C++ with a self-test): a fixed satellite
  constellation above the elevation mask; every epoch traces one ray per satellite from the antenna through the
  world's canopies (cylinders read from the scene tree) and sums the foliage chord crossed. The visible satellites
  set the state (RTK fixed / float / single / no fix) with re-acquisition hysteresis; Gauss-Markov error per state;
  multipath jumps at a rate proportional to the blocked sky (which the receiver does **not** reflect in its σ);
  no-GNSS zones; random outages; latency with a timestamp.
- **The four configurations run at once** on the same data (openfield shadow filters): A = current EKF;
  B = receiver R + Student-t + latency compensation; C = no GNSS after initialisation; D = no IMU yaw. The comparison
  therefore does not depend on two runs seeing different data.
- **No-GNSS zone**: the y ∈ [−2, 6] stretch of the x = 3.75 corridor (`DeniedZones`).
- The report's "fix error" measures only the added degradation (delivered fix against the Webots GPS reading); the
  filters' errors are measured against the simulator's ground truth.

## Pieces

| Script | What it does |
|---|---|
| `run_experiment.py` | One run: applies the variant, starts Webots + sensorimotor layer + cognitive layer, waits for every agent to be *Operating*, starts the recorder, the monitor and the driver, stops everything and collects the logs |
| `recorder.py` | **Read-only** DSR agent (id 97): estimated pose and Webots ground truth at 10 Hz; people, trunks, obstacles and occupied residual cells at 1 Hz; presence state of every agent; pose rate and age |
| `sysmon.py` | CPU, RAM and GPU memory per process, every 2 s |
| `gt_driver.py` | E1 driver: pure pursuit on the **simulator's ground truth**, so the route is identical in every run and does not depend on the estimator being measured |
| `screenshots.py` | Screenshots of Webots, the controller map, the openfield trajectories, the DSR graph, retina and the ZED/YOLO window |
| `gen_worlds.py` | E2 world: four workers (crossing, behind the vegetation, behind the robot) |
| `analyze_e1.py`, `analyze_people.py`, `analyze_map_nav.py` | Metrics, tables and figures of E1, E2 and E3–E5 |
| `summary.py` | Runs the analyses and joins the reports into `results/SUMMARY.md` |
| `batch.sh` | Runs a list of `EXP VARIANT SEED` lines one after another |

Each run is stored in `results/<EXP>/<world>__<variant>__s<seed>/` (`run.json` with the starting commit, `git.diff`
with the uncommitted changes if any, `record.jsonl`, `sysmon.jsonl`, `driver.log`, `cfg/`, `logs/`, `openfield/`,
`screenshots/`). The analyses only read those folders and can be re-run at will.
